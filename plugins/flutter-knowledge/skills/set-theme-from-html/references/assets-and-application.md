# Asset import and foundation application

Source extraction remains owned by [source-extraction.md](../../html-to-widget/references/source-extraction.md); token APIs and policy remain owned by [flutter-app-theme](../../flutter-app-theme/SKILL.md). This reference owns the asset-to-project handoff.

## Resource inventory

Collect rendered `img.currentSrc` alongside `src`/`srcset` candidates, CSS background/mask/list-image resources (including pseudo-elements), SVG/inline sprites/defs/uses and declared font faces. Follow actual navigation and supplied modes/states, CSS imports and resource bases. A rendered choice does not imply other responsive candidates were checked. Browser resource timing is supporting dependency evidence, not a complete inventory of local, embedded or unused resources. Record unavailable CSSOM and dependencies affecting runtime states. Materialize relevant local/data/public resources and hash their bytes; bounded network GETs are limited to referenced resources. Never log URL credentials or sensitive queries. Unsupported blob/authenticated resources require a supported source export or exact missing resource report, not a substitute.

Resolve each reference against the HTML/document base or stylesheet's actual URL. Preserve original bytes and format. Keep images and icons under the existing `assets/images` and `assets/icons`, fonts under `assets/fonts` or the project's established subdirectory. Deduplicate by byte hash and kind; names must stay readable and stable, collisions must not overwrite unrelated files. Reruns reuse imports and declarations. Retain source-provided license files/notices with their assets and provenance; if absent record the absence rather than inventing a license or silently assuming one.

## SVG and fonts

For standalone SVG preserve defs, gradients, clipping, nested uses and inherited styling. Inline markup must include referenced defs/symbols from its source document, explicit namespace/viewBox and captured inherited color/style context, including currentColor provenance. Copy actual original nodes; inspect the resulting render. A consumer must keep the source element's CSS box, not the viewBox aspect ratio, or adjacent labels shift. Missing/external ids, unresolved stylesheet selectors, unsupported filters/masks or source-dependent animations are gaps until resolved through a fidelity-preserving export. Do not strip them to make a decoder accept the file. The importer rejects unresolved references and unsupported external resources; it does not automatically make inline SVG portable.

Font evidence distinguishes declared, loaded and used families. Verify container format and font metadata, weight/style/variable axes and glyph coverage for supplied content/locales. Preserve actual family, style and weights in pubspec and AppFonts; repeated faces can share bytes without inventing separate font weights. A static font requested as multiple weights may indicate synthesized browser weights: record it and establish the installed Flutter equivalent instead of claiming separate original faces. Converting WOFF/WOFF2 or instancing a variable font requires an actual installed Flutter/API constraint, reproducible tool/axis settings and source-byte provenance; never convert or substitute silently. Report missing glyphs/faces or unsupported formats before dependent implementation. Use the [effective font-plan audit](foundation-proof.md#font-plan-audit): match bound CSS declarations/visible usages against the actual pubspec/AppFonts aliases, variable axes, selected faces and ordered fallback chain. Subsets are not weights, and unused imported faces cannot rescue selected coverage.

## Project edits

Inspect existing AppAssets and callers. Preserve `_images`, `_icons`, `_translations`, its `translations` getter and existing typed constants. Extend readable named constants for successfully imported assets, without source-machine paths. Add only the necessary pubspec asset and font declarations. Existing parent directory declarations can cover new files; do not duplicate them or replace dependency/config sections. The importer returns files/font metadata and suggested paths; the agent must make small intentional edits, not blindly rewrite arbitrary Dart/YAML.

Map measured source roles to every affected token group and Material/component theme through the owning theme conventions. Shared controls should consume the applicable semantic slots/text/radius/space/elevation/motion/shape defaults. Preserve selected image/SVG/font/package adapters and public wrapper parameters. Multiple source variants use existing variant APIs or a scoped extension through UI conventions; conflicting common defaults require evidence-backed role choices. Do not replace a working component with a raw widget to bypass its theme. Unprovided modes/roles keep explicit provenance such as `unchanged`, `derived` or `provisional`; applying an existing dark skin is not evidence that the source supplied one.

Follow [foundation-proof.md](foundation-proof.md) for exact semantic roles, actual component defaults/variants, paint consumers and the immutable stage audit. A source-role mapping row should retain profile/selector/state, property and measured value, mapped token/asset, affected consumer and evidence status. Keep implementation decisions distinct from observed source facts. Hashes validate byte identity; full mapping plus actual source-backed captures and inspection establish only the checked foundation scope.
