# Core contracts

This reference identifies what core setup must connect. Apply only the responsibilities selected by `flutter-core`; the full inventory and startup recipe do not expand a task-scoped completion. Detailed naming, token and data recipes remain in their owning skills; do not copy their full guidance here. The inspection JSON lists conventional paths, but actual custom contracts and callers take precedence where the owning conventions allow them.

## Default contract map

| Area | Public contract and completion evidence |
| --- | --- |
| Root/entry | `MyApp` in `lib/my_app.dart`; `lib/main.dart` directly performs startup and constructs it. Preserve root behavior; the default get_it root is `const MyApp({super.key})` with no container field/parameter; no `CoreApp`, `core_app.dart`, `app_bootstrap.dart` or replacement production bootstrap helper. |
| Router | `AppRouter.navigationKey`, `scaffoldMessengerKey`, `generateRoute(RouteSettings)` and `static String get initialRoute` containing the entry decision, including a root-only `/` app; sealed `RoutesStrings` part; `Navigation` part provides push/pop helpers. Import the router library, not its parts. Preserve existing entry/routes and route-owned provisioning. |
| DI | Default get_it defines `final GetIt sl = GetIt.instance;` in `core/di/injection.dart`; registration and resolution import that global directly. `registerCoreDependencies()`, `registerAppDependencies()` and feature registrations take no container parameter; app registration calls core then features. Widgets/routers have no locator property or parameter. Resolve actual consumer/client, NetworkStatus and SkinRegistry; root owners have appropriate factories/lifetimes. Use explicit `sl<T>()` without shadowing `sl`; keep actual service constructor injection and selected alternative DI mechanics. |
| Tokens | `AppTokens extends ThemeExtension<AppTokens>` exposes `skin`, `space`, `radius`, `text`, `elevation`, `motion`, `shape`, `copyWith`, `lerp`, built-in instances and `of(AppSkin)`; `context.tokens` reads the registered extension. |
| Theme | `AppTheme.light`, `.dark`, `.of(skin)` build fresh ThemeData with token/skin ColorScheme and component mappings. Root uses this theme instead of independent per-feature ThemeData. |
| Skins | `AppSkin` has identity, mode, localized name and equality by id; LightSkin/DarkSkin supply required palette roles. JsonSkin validates required roles/overrides. `SkinSource`, `AssetSkinSource`, `SkinParser`, load result and `SkinRegistry.load/skins/byId/builtInFor` support a list of built-in and JSON skins. Bad/duplicate skins are reported without inventing valid values. |
| Skin state | Root-owned `SkinCubit` stores `skin`, exposes `skins` and `select`, restores/persists selection through preferences. Its part state file and equality follow the theme/state contracts. ThemeSheet shares the existing owner and lists available skins. |
| Token groups | AppSpacing scale/screenH/tap targets; AppRadius scale and component radii; skin-colored AppElevation; AppTypography/AppFonts/FontWeightHelper; AppMotion durations/curves/offsets/staggers; AppShapes. All seven responsibilities remain accessible. Morphing polygons/springs are optional capabilities with configured installed APIs, not incidental dependencies. |
| HTTP | ApiConsumer supports get/post/put/patch/delete with real body/query/options forwarding; default DioConsumer receives its configured client, centralizes options/interceptors and throws Failure for transport errors. Do not leak transport handling into features. Honor validation parsing on every applicable verb and form-data behavior if the API exposes it. |
| Envelope | Nullable `GlobalResponse<T>.status/message/data`, `isCached`; `fromJson` supports wrapped/unwrapped payloads and decoder, translating parsing errors to MappingFailure. Test actual null/list/map envelopes when requested; do not assume every payload is a non-null map. |
| Results/errors | `FutureResult<T>`, Result.success/failure/when and the existing Failure hierarchy: LocalFailure, MappingFailure, ServerFailure including noNetwork, UnauthorizedFailure. Default Dio error translation covers cancellation, timeouts, connection, unauthorized, validation and unexpected response cases without returning fake success. |
| Endpoints | Sealed EndPoints, static base URL/constant endpoints and methods for runtime parameters. Preserve the data-layer convention: no environment file or dart-define URL policy. When no URL is supplied, retain an explicit empty configuration value and report it; no invented server or reference-app backend. |
| Network | NetworkStatus exposes `Future<bool> isConnected` and `Stream<bool> onConnectivityChanged`. Use the selected implementation. `NetworkCubit` in `services/network/logic/` is the root connectivity owner on the Bloc stack; use the existing configured NetworkStatus without duplicating or replacing it. Its part states are payload-free `NetworkInitialState`, `NetworkOnlineState`, `NetworkOfflineState`; it exposes owner-held `isOnline` and broadcast `onRestored`. Link connectivity does not prove Internet or backend reachability. |
| Cache/logger | Ordinary `CacheHelper`/`CacheKeys` plus `SecureCacheHelper`/`SecureCacheKeys`, following [cache storage](#cache-storage); selected AppLogger behind debug/reporting calls. Preserve existing application keys. Do not add session/account policy. |
| Layout | Breakpoints, WindowSize/fromWidth and context size/inset helpers. Component layout still uses its parent's constraints. Core locale/context extension supplies isRtl/isLtr from Directionality, preserving language-specific helpers separately. |
| Localization | Default AppLocales/en/ar resources (shared strings in a `common` group)/generated LocaleKeys; matching natural translations and actual generator. Other selected backends use their own resources/accessors without parallel infrastructure. |
| Main wrappers | AppText; AppScaffold/GlobalAppbar; AppContainer; ordinary/sliver spaces; PrimaryButton/SecondaryButton/AppIconButton/AppInkWell; AppTextField; showAppSheet/AppBottomSheet/ThemeSheet; AppLoader/AppErrorWidget and snackbar helper. One widget class per file except the shared spacing family; tokenized defaults, meaningful disabled/loading states, localized semantics, grow/scroll with text. |

GlobalAppbar is a conventional wrapper but is absent from the reviewed reference app. When required, create a minimal tokenized PreferredSizeWidget instead of pretending it was copied from that reference.

## Cache storage

Classify a value before persisting it. Bearer/access/refresh tokens and other session secrets belong only in `SecureCacheHelper` using `SecureCacheKeys`; theme/skin, locale and non-sensitive onboarding flags belong in ordinary `CacheHelper` using `CacheKeys`. Apply the same distinction to reads, refresh, removal and existing logout flows. Never duplicate secrets in preferences, a normal local database, logs or UI state. Do not persist passwords as a convenience.

The default secure backend comes from `packages.secure_storage` in the initializer catalog, independently of preferences and local database choices. A missing selected dependency is needed by this core responsibility; declare and resolve it without upgrading unrelated packages. Preserve an equivalent existing secure implementation. An alternative must provide verified secure storage on the target platforms. If configured `none`, report the blocked responsibility; never substitute plaintext or silently change the selection.

Use the reference pattern under `lib/core/data/cache/`:

- `cache_helper.dart` owns ordinary `CacheHelper`; `cache_keys.dart` is its part. With SharedPreferences, keep async `init`, `Future<bool> save(String key, dynamic value)`, synchronous `dynamic get(String key)`, and async bool-returning `remove`/`clear`. Support its standard String, int, bool, double and List<String> values; null saves return false and unsupported types raise UnsupportedError. Read the selected backend's cached typed values rather than narrowing the helper to a string-only memory mirror. Preserve a working existing API's supported values and verified alternative-backend semantics.
- Await ordinary mutations and preserve the last confirmed backend view on failure. The reviewed SharedPreferences 2.5.6 setters/removal update their cache before the platform result; a false/throw must not reappear as a saved value after reopening. Serialize overlapping mutations and recovery, reload the backend view after failed changes, and make reads unavailable if recovery fails until initialization succeeds. Verify false/throw and reopen behavior at the storage boundary, not only with a mocked repository.
- `secure_cache_helper.dart` owns sealed static-only `SecureCacheHelper`; `secure_cache_keys.dart` is its part with sealed `SecureCacheKeys` (for example `accessToken` and `refreshToken`). Keep existing key strings when completing a project.
- The `SecureCacheHelper` contract provides async `init`, `save(String key, String value)`, `remove` and `clear`, plus synchronous `String? get(String key)` backed by a private in-memory map hydrated during awaited initialization. Reads before successful initialization must not masquerade as missing credentials. Use the installed storage API behind this helper, not directly in features. Preserve a working custom async contract and adapt its callers instead of introducing another helper.
- Confirm durable writes/deletions before updating the memory mirror. Serialize overlapping initialization/mutations so a late preload/write cannot resurrect a removed value. Propagate failures through the existing error boundary without sensitive values. A read failure must not delete all persisted credentials, return fake success, or fall back to ordinary preferences. Disable backend destructive reset behavior where supported (`AndroidOptions(resetOnError: false)` in the reviewed API); a wrapper cannot promise preservation if its backend silently wipes data. Keep memory and disk failure behavior explicit.
- Preserve existing reinstall/account/logout policy. Do not copy a first-run marker that deletes Keychain contents into every app. If tokens already exist in ordinary preferences, migrate only identified credential keys: prefer an existing secure value, otherwise await a successful secure write before deleting its plaintext copy. A failed move retains the original for retry and is reported as incomplete. Update all affected readers/writers and logout cleanup together, retaining unrelated preferences.

Inspect [the package documentation](https://pub.dev/packages/flutter_secure_storage) and the target's resolved version before choosing options. The reviewed reference uses `IOSOptions(accessibility: KeychainAccessibility.first_unlock_this_device)`; preserve target policy and verify that option in the installed API. Use ordinary Android secure storage without adding biometric gating by default. Do not copy deprecated `encryptedSharedPreferences` setup into current releases.

## iOS and Android setup

For every core package actually integrated, inspect its resolved-version installation instructions and both native targets. Apply required Gradle/SDK, manifest, Podfile/deployment-target, Info.plist, entitlement and startup changes within this core task. Verify API/network access in the release-effective Android manifest rather than relying on debug-only permissions; preserve normal HTTPS transport without blanket cleartext/ATS exceptions. Preserve existing flavors, signing, identifiers and permission descriptions; do not duplicate entries or add capabilities for unused features. If a platform directory is absent, report that target as unavailable rather than claiming support or overwriting platform scaffolding.

For secure storage, check the package's Android minimum SDK and encrypted-store backup/restore requirements. Resolve documentation/source conflicts against the actual installed build constraints: the reviewed 11.2.0 README says API 23, while its `android/build.gradle` requires `minSdk = 24`. Exclude the installed backend's secure data/key files from applicable cloud backup and device-transfer rules, or disable backup where appropriate to the app's existing policy; do not restore encrypted credentials without their device keys. Inspect both legacy backup rules and newer data-extraction rules where applicable. Verify cipher migration options against the installed source.

On iOS, follow the resolved package's Keychain capability/access-group requirements. Wire the entitlement files to the actual Debug, Profile, Release and flavor build configurations; merely creating a file is insufficient. Preserve real application prefixes/groups and verify the deployment target against the resolved Darwin plugin. Basic secure storage does not require camera, location, storage or biometric permissions. Add biometric/Face ID declarations only when the app explicitly uses that mode. For other selected core packages, add required permissions and implement runtime permission requests at the owning feature/use site when necessary; a manifest or usage string alone does not grant access.

For easy_localization, declare the configured supported locales in iOS `CFBundleLocalizations` (English/Arabic on the default stack), preserving additional existing locales. Inspect the effective built Info.plist when a build is available; a host test forcing Arabic does not verify native bundle language metadata. Other localization backends keep their verified native installation requirements.

Validate native files and run targeted Android and iOS builds when the toolchains/targets are available, honoring project execution restrictions. Exercise a disposable secure key through write/read, restart/read and delete/read on each available native runtime, cleaning up only that key; verify ordinary preferences remain independent. Retain platform/error evidence without secret values. Mocked channel tests check helper behavior, not Keychain/Keystore configuration. Report configuration inspection, build and runtime results separately per platform, with unavailable signing, SDK, device or permission checks explicitly unverified. Do not claim both platforms work from compilation or host-only tests.

## Startup order

Perform these steps directly in `lib/main.dart`, keeping target-specific policy and constructor parameters. Copy [the canonical command block](main-command-block.dart.txt) verbatim to the bottom of `lib/main.dart`, after `main()`, for core setup (never at the top or with a `library;` directive); these comments are the explicitly authorized exception to no-comments rules and never an instruction to run commands or install mentioned packages.

1. Ensure Flutter binding.
2. Run the independent initializations concurrently in one awaited `Future.wait<void>([...])`: the selected localization runtime (`EasyLocalization.ensureInitialized()` on the default stack), `CacheHelper.init()`, `SecureCacheHelper.init()` and any other target init that needs none of the others. Await it before DI consumers, root state or initial-route decisions read cached values; steps that depend on an earlier result (DI registration, SkinRegistry load, observer) stay sequential after it. For another selected secure backend preserve this readiness boundary; `none` cannot satisfy sensitive persistence.
3. Register app dependencies: complete core infrastructure first, then existing features.
4. Load SkinRegistry before constructing SkinCubit, so a persisted custom id resolves.
5. Initialize required resources before resolving consumers; no incidental database creation.
6. For selected `flutter_bloc` / `bloc` with Talker, assign `Bloc.observer` a `TalkerBlocObserver` using the already registered shared Talker after DI and before any root Cubit is created. Verify installed observer APIs and add `talker_bloc_logger` only when used. Use debug-gated logs and disable full event/state data. In 5.1.20 `onError` bypasses settings: use a narrow subclass to log error/runtime types only in debug, forwarding only `error.runtimeType` and `StackTrace.empty` to `super.onError` inside the debug guard; this honors the installed API’s `@mustCallSuper` annotation without leaking payloads. Other selected state backends must not gain Bloc imports/dependencies; preserve selected logging mechanics through a verified adapter.
7. Run `MyApp` under its configured localization provider.
8. Root owns skin/network state and selective rebuilding; configured typography initialization wraps MaterialApp when needed.
9. MaterialApp gets AppTheme.of(owner.skin), localization delegates/locales/current locale, router and keys, preserving the target entry screen.

The reviewed fixture's core DI only registered AssetBundle/SkinRegistry; that is not a complete production registration graph. Verify every requested core dependency can resolve.

## Completion of existing projects

Inspect current contracts, implementations and call sites first. Extend incomplete APIs without replacing working constructors or changing the callers' behavior. Existing custom mappings and several candidate files need inspection, not automatic duplication. Preserve feature dependency lines, cache keys, translations, fonts/assets and palette overrides. Complete missing registrations/providers exactly once. A second invocation with no changes should have an empty edit plan.

Separate common foundations from application policy. The reference app's onboarding/setup completion, authentication redirects, chat tables, personal socket, recorder/permissions, personalization and screen-specific tokens are not generic core. Its labels/assets/endpoints are not defaults for another app.

For package adaptation, read the configuration contract and only relevant package-adaptation sections. Unknown selected APIs remain a disclosed adaptation task rather than permission to change the YAML selection. Default discovery of classes/methods is not evidence that another backend is incomplete.

## Core API alignment

These are generic contracts derived from the reference app's shared core. Preserve target constructor parameters and token behavior where they already exist.

- Assets: create sealed `AppAssets` in `helpers/app_assets.dart` with `static const String _images = 'assets/images';`, `static const String _icons = 'assets/icons';`, `static const String _translations = 'assets/translations';`, and `static String get translations => _translations;` even when image/icon directories are empty. Create those directories as appropriate, without invented files or unnecessary empty asset declarations. Derive verified image/icon constants from their prefix while preserving names. Public `images`/`icons` directory getters may reference otherwise unused private prefixes; do not suppress broad lint gates. Presentation callers use its named constants rather than literal/interpolated asset paths. Preserve a working existing `AppAsset` equivalent; never import reference-app branding or nonexistent placeholder assets into another app.
- Dio errors: `data/error_handling/dio_error_handler/dio_error_handler.dart` owns `DioErrorExtension.getFailure`; `DioConsumer` calls it directly from its Dio exception boundary. A response helper may live beside it. Keep the target Failure hierarchy, typed validation decoding and body/query/options/cancellation forwarding on every applicable verb. Do not add the reference app's session redirects.
- Startup: `AppRouter` owns the entry decision directly in public `static String get initialRoute`; MyApp only reads `AppRouter.initialRoute`. Do not add a redundant private forwarding getter or move policy into MyApp. A root-only router returns `RoutesStrings.root`. Existing onboarding/token/setup decisions belong in this getter only when the target already implements them; no invented business policy.
- Loader: preserve `const AppLoader.center({super.key, this.color}) : isCenter = true` and the ordinary constructor with `isCenter = false`; provide pagination convenience when applicable. Use the target loader color token. Supplied expressive loading uses `LoadingIndicator(activeIndicatorColor: ...)`; a filled morphing shape does not implement a stroked arc's width.
- Images: keep `AppSvgImage`, and make it occupy the requested `width`/`height` box (wrap `SvgPicture` in a `SizedBox`); `flutter_svg` otherwise shrinks a non-square viewBox to its aspect ratio, while browsers letterbox it inside the declared box. Add `AppAssetsImage(imagePath, {key, height, width, fit, opacity})` and `AppNetworkImage(imageUrl, {key, fit, width, height, errorWidget, placeholder})` under `widgets/images`. Asset defaults use cover; network defaults use contain and viewport width for unspecified width/height, matching the reference app; preserve existing target sizing overrides. Verify installed cached-image APIs or adapt to the selected image loader; use target-backed or empty fallback UI rather than a reference-app asset.
- Fields: callers must explicitly supply `AppTextField.textInputAction`; preserve nullable type if already public, but make the constructor argument required. Update existing callers and tests.
- Spacing: all four classes share `widgets/layout/space_widgets.dart`: `VerticalSpace(height)`, `HorizontalSpace(width)`, `SliverVerticalSpace(height)`, `SliverHorizontalSpace(width)` with `super.key`. Ordinary variants return SizedBox, sliver variants SliverToBoxAdapter. Consolidate imports and safely remove redundant split implementations. This family is the owning UI skill's explicit exception to one widget per file.
- Dio logging: on the Talker stack, `AppInterceptorLogger extends TalkerDioLogger` lives in `data/api/app_interceptor_logger.dart`, accepts `talker`, `settings`, and `convertFormData`, and renders a cURL representation from `onRequest`. `DioConsumer` installs this interceptor in debug mode using the selected Talker instance without duplicate installation. Sanitize independent logging copies before both cURL and inherited request/response/error logging: authorization/cookies/API keys, URI credentials, sensitive query/body fields and nested/form-data values. Never mutate the real request or response to redact logs. Report the redaction divergence from the reference app. Normal certificate validation, injected Dio/client options and actual setters remain intact. Alternative logging backends retain these responsibilities through verified adapters.

## Root network ownership

For configured `flutter_bloc` / `bloc` with get_it, register `sl.registerFactory<NetworkCubit>(() => NetworkCubit(sl<NetworkStatus>()));` in canonical core injection. MyApp uses `MultiBlocProvider` with normal `BlocProvider<NetworkCubit>(create: (_) => sl<NetworkCubit>(), lazy: false)` and the existing SkinCubit provider. Eager creation starts monitoring on root mount even before a consumer reads it. The provider owns and closes this instance; consumers use `context.read<NetworkCubit>()` / `watch`, never another factory lookup for the active owner. Do not register NetworkCubit as a singleton or use `.value` for this root owner. Sharing an already-owned screen cubit with `.value` remains valid. Other configured state/DI backends keep their verified creation/disposal equivalent without adding Bloc or get_it.

Subscribe before starting the initial check. Until the first resolved value, keep NetworkInitialState; a first online result is a resolution, not a restoration. Suppress duplicates, emit one restoration per resolved offline-to-online transition and discard an initial result once a newer stream value exists. Report initial-check, subscription and stream errors through the selected observer/error boundary without inventing connectivity results. Mark disposal before asynchronous cleanup, await owned subscription cancellation and controller closure, and complete owner closure even if cancellation fails. An uncancellable external initial-check future must not hold disposal open; guard both its late result and error. No state/flag/restoration changes may occur after disposal starts. Verify these lifecycle boundaries with the selected installed APIs.
